# MicroFlow 一键启动与主机网线直连

## 1. 一根网线直连为什么曾经掉线

2026-10-23 实测：主机 `enp8s0` 与板子 `end0` 的物理链路正常，
原有配置却依赖 DHCP。直连线上没有 DHCP 服务，连接超时失败后，
NetworkManager 移除了临时 IPv6 地址，因此短时间能 SSH，随后出现
`Network is unreachable`。这不是 SSH 密码错误或 MicroFlow 推理崩溃。

两端现在新增独立的 `rock4d-direct` 配置，IPv4 与 IPv6 均使用链路本地模式，
不需要 DHCP，也不配置默认网关或 DNS，不共享上网。不修改 Wi-Fi、VPN 或防火墙。
原校园网有线配置保留。专用配置自动连接优先级为 100。

链路本地 IPv4 为 `169.254.x.x/16`，IPv6 为 `fe80::/64`。
配置重建、地址冲突或网卡变化时地址可能改变，不能把本次地址当永久固定 IP。

## 2. 连接和查询

本次部署实测地址（2026-10-23，地址发生变化时以查询输出为准）：

- 主机 `enp8s0`：`169.254.73.236`。
- 板子 `end0`：`169.254.167.249`。
- 板子有线 IPv6：`fe80::8586:f044:475d:f2d7`。
- 主机浏览器：`http://169.254.167.249:18080/`。

```bash
ssh michael@169.254.167.249
```

主机侧：

```bash
sudo nmcli connection up rock4d-direct
ip -br address show enp8s0
```

板子侧：

```bash
ip -br address show end0
```

使用板子的有线 IPv4 连接：

```bash
ssh michael@板子有线IPv4
```

IPv4 尚在选址时，可以用有线 IPv6 连接，`%enp8s0` 是主机出口网卡，不能省略：

```bash
ssh -6 -o HostKeyAlias=rock4d.local michael@板子fe80地址%enp8s0
```

注意：`rock4d.local` 也可能解析为 Wi-Fi 地址；验证网线直连时明确使用有线地址。

## 3. 板端一条命令启动

```bash
cd /home/michael/Micro_flow_PI4
bash setup.sh
```

默认执行以下步骤：

1. 检查模型与依赖，离线使用现有源码构建 Release；已有 `build-opt3` 缓存时复用它，
   否则使用 `build-rock4d`。不会从电脑整库覆盖板端代码。
2. 执行 CTest 回归检查。
3. 安装并启用 `microflow-web.service`，使用项目普通用户运行，默认四线程；
   在可用的 ARM64 CPU 4～7 上固定亲和性。
4. 启动 HTTP 前端、`/health`、`/predict`、`/visualize` 和集成的 C++ 模型推理。
5. 检查主页、内置真实手写 7 预测、特征图接口及非法输入拒绝，打印访问地址。

服务由 systemd 托管，关闭 SSH 后继续运行，下次开机自动启动，异常退出时有限重试。
无需安装 Node.js、启动 Python 模型服务或长期运行基准测试。
它不会启动、停止或修复 Tailscale，也不自动训练或下载数据。

依赖缺失时先手工准备：`build-essential cmake python3 curl iproute2`；项目本身还需要 OpenMP。
脚本只提示缺失项，不擅自安装软件。首次安装可能提示输入 sudo 密码。

重复运行不会创建重复服务，配置相同时不会重启已经运行的服务。
端口被非本服务进程占用、同名 unit 不是本脚本管理时，拒绝覆盖或强杀。

## 4. 主机访问

在主机浏览器输入脚本打印的 **板子有线 IPv4**：

```text
http://板子有线IPv4:18080/
```

使用 HTTP，不是 HTTPS。当前 Web 程序监听 IPv4 `0.0.0.0`，因此浏览器优先使用
有线 IPv4；IPv6 在此主要用于直连管理。不要直接把 IPv6 地址套入 IPv4 URL。

页面可以手写数字并识别，查看分类概率与中间层特征图。

主机终端健康检查：

```bash
curl --noproxy '*' --max-time 5 http://板子有线IPv4:18080/health
```

如果主机有代理软件，不应把 `169.254.0.0/16` 的直连请求发给代理。
curl 命令已经明确禁用代理；浏览器若失败，应检查代理的局域网绕过配置，
不要直接关闭整个防火墙或改动全局路由。

## 5. 状态、日志、停止和自定义

以下在板端项目目录执行：

```bash
bash setup.sh status
bash setup.sh logs
bash setup.sh restart --no-build --skip-tests
bash setup.sh stop
```

`stop` 同时取消开机自启；重新执行 `bash setup.sh` 会重新启用。
日志也可以用 `sudo journalctl -u microflow-web.service -n 80 --no-pager` 查看。

```bash
MICROFLOW_PORT=18081 MICROFLOW_THREADS=4 bash setup.sh
```

自定义变量包括 `MICROFLOW_BUILD_DIR`、`MICROFLOW_MODEL`、
`MICROFLOW_BIG_CORES`、`MICROFLOW_BUILD_JOBS`。端口范围为 1024～65535。
空的 `MICROFLOW_BIG_CORES=` 表示不固定 CPU。
环境变量在调用脚本时使用，安装后的服务不依赖 SSH 会话保留这些变量。

## 6. 网线重新接回校园网时

专用直连配置优先级较高，不会自动判断网线另一端是板子还是校园网交换机。
如果主机网线改接校园网，请手动选择原配置：

```bash
# 主机执行；会改变主机有线连接，但不修改 Wi-Fi
sudo nmcli connection up netplan-enp8s0
```

板子若改接校园网，则选择原 `Wired connection 1`：

```bash
# 板端执行；先确认现场有其他管理通道
sudo nmcli connection up 'Wired connection 1'
```

再次直连时两端选择 `rock4d-direct`。若不希望该配置自动抢选，可手动将
`connection.autoconnect` 设为 `no`，以后每次直连显式执行 `connection up`。

## 7. 可复现验收

```bash
# 板端：构建与 C++ 回归
bash setup.sh test
# 无特权脚本参数与 unit 渲染测试
python3 tests/test_setup.py
# 在板子或主机上验证实际 HTTP；主机使用本机存在的样本文件路径
python3 tools/check_service.py http://板子有线IPv4:18080 image/test_input.bin 4
```

上述样本验收不能替代完整 MNIST 准确率测试。有限时间的连接复测也不能证明无限期稳定。
